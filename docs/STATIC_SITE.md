# Публичный сайт без засыпания

Два независимых сервиса: Render Static Site для посетителей и существующий Render Web Service для кабинета. Neon остаётся только у кабинета. Статическая сборка не подключается к базе и не делает HTTP-запросов к кабинету. Кнопка входа переводит посетителя в кабинет, который на Free может просыпаться около минуты.

## Публикация

1. Отправить изменения в GitHub.
2. Render → New → Static Site → тот же репозиторий и рабочая ветка.
3. Name: mus-kz-public (или свободное название). Root Directory: пусто.
4. Build Command: `pip install -r requirements-static.txt && python scripts/build_public.py`
5. Publish Directory: `dist-public`
6. Environment: `CABINET_URL=https://mus-kz.onrender.com` (без /login).
7. Не добавлять DATABASE_URL, SECRET_KEY и другие секреты кабинета в статический сервис.
8. Создать сервис и проверить главную, фото, контакты и кнопку входа. Новый адрес распространять среди родителей. Старый адрес оставить для кабинета. Не удалять Web Service и Neon.

## Обновление публичных сведений

Источник — `public/content.json`, первоначально экспортирован из локальной базы. Если данные на Neon уже менялись, перед публикацией сверить содержимое с опубликованным сайтом. JSON содержит только видимые на главной поля, без учеников, балансов, паролей и закрытых ссылок Meet.

Можно редактировать JSON напрямую (курсы, набор, контакты) и отправлять коммит: Render пересоберёт статический сайт. Изменение данных в кабинете само по себе не обновляет публичный сайт.

Для экспорта из нужной базы: запустить `python -m app.export_public` в окружении с её DATABASE_URL и сохранить UTF-8 stdout в public/content.json. Не использовать PowerShell 5 перенаправление `>` без контроля кодировки; запускать через Python subprocess и write_bytes. Не подменять локальную базу копией Neon ради экспорта. Экспорт публикует ровно поля главной страницы.

События в прошлом исключаются на момент сборки. После изменения/отмены набора или события обновить JSON и пересобрать сайт. Все динамические страницы, вход, расписание, отчёты и оплаты продолжают работать в прежнем кабинете.

## Локальная проверка

Установить requirements-static.txt, задать CABINET_URL и выполнить `python scripts/build_public.py`. Затем `python -m http.server 8081 --directory dist-public` и открыть http://localhost:8081. Главная должна работать при остановленном backend.
