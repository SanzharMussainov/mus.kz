# Эксплуатация

## Простое размещение в пределах 50 000 ₸ на запуск

Один Linux VPS: приложение + PostgreSQL + закрытый volume файлов. Начальная конфигурация — 2 vCPU, 2–4 ГБ RAM, 25–40 ГБ SSD, затем по фактической нагрузке. Управляемая БД, Redis, Kubernetes и платные API не требуются.

На 12.10.2026 официальная [страница Hoster.kz](https://hoster.kz/cloud/vps/) показывает начальный Cloud 1-1-25 (1 vCPU, 1 ГБ, 25 ГБ) за 3 100 ₸/месяц. Это нижний ориентир, а не рекомендация брать 1 ГБ для БД и приложения. Перед покупкой проверьте актуальную цену конфигурации от 2 ГБ и резервных копий. Сравнить условия можно с [PS Cloud Services](https://www.ps.kz/). Покупка не выполнялась.

Рабочий бюджет распределите как лимиты, а не как обещанные тарифы: до 15 000 ₸ на первый месяц VPS; до 15 000 ₸ на домен при необходимости; до 5 000 ₸ на отдельную копию; 15 000 ₸ резерв. Если 50 000 ₸ — бюджет за весь год, это требует отдельного пересчёта: не следует тратить его на сервер, рассчитанный только на первый месяц. Домен mus.kz в коде — название проекта, владение им не проверено.

## Подготовка сервера после согласования публикации

1. Установите Docker/Compose на VPS. Разместите код и `.env` с новыми секретами. Используйте чистые volumes, не переносите демонстрационные аккаунты.
2. Выполните команды запуска и создания администратора из README. Заполните публичные данные, контакты, реальные программы и ссылки Meet.
3. Укажите DNS домена на сервер и настройте HTTPS reverse proxy (например, Caddy) перед `127.0.0.1:8000`. Пример Caddyfile:

```caddyfile
your-domain.kz {
    request_body {
        max_size 11MB
    }
    reverse_proxy 127.0.0.1:8000
}
```

4. После включения HTTPS задайте `COOKIE_SECURE=true` и пересоздайте web: `docker compose up -d web`. Не публикуйте PostgreSQL и каталог файлов. Внешне доступны только 80/443 и администрирование сервера согласно вашим правилам.
5. Проверьте вход с телефона, скачивание файла, подачу заявки, выдачу работы и резервное восстановление. Перед использованием с настоящими учениками заполните информацию об обработке данных под реальные процессы проекта.

## Резервное копирование

Запускайте из корня проекта. На хосте нужен Python и Docker Compose:

```sh
python scripts/backup.py --output backups
```

Скрипт временно останавливает web для согласованной копии БД и файлов, создаёт PostgreSQL custom dump, tar файлов и SHA-256 manifest, затем возвращает web в работу. Короткое окно недоступности планируйте вне занятий. Создайте ежедневный запуск штатным планировщиком сервера; он здесь не подключён. Храните, например, 7 ежедневных и 4 еженедельных копии. Копируйте их на отдельное защищённое хранилище, а не только на тот же VPS. `.env` храните отдельно в защищённом менеджере секретов.

## Восстановление

Используйте отдельный каталог с кодом и `.env`, новый `COMPOSE_PROJECT_NAME` и пустые volumes. Не запускайте web до восстановления — миграция создаст таблицы и скрипт корректно откажется писать поверх них.

```sh
docker compose build web
docker compose up -d db
# Дождитесь healthy в docker compose ps
python scripts/restore.py /path/to/backups/20261012T180000Z
```

Скрипт проверяет контрольные суммы, пустоту базы и файлового volume, восстанавливает БД и файлы и запускает web. При обнаружении непустого хранилища останавливается без удаления данных. После восстановления проверьте баланс контрольного ученика, историю операций и скачайте один файл. Только после успешной проверки переключайте DNS/прокси. Проверяйте восстановление регулярно.

## Обновление

Сначала резервная копия; затем новая версия кода, `docker compose up -d --build`. Перед обновлением схемы проверьте миграции на копии данных. В проекте одна начальная миграция. При изменении моделей создавайте новую миграцию, не редактируйте уже применённую. Для отката с изменениями данных используйте проверенную резервную копию.

## Мониторинг и ограничения

Проверяйте свободное место файлового volume, ошибки `docker compose logs web`, срок сертификата и успешность копирования. Файлы до 10 МБ, PDF/JPEG/PNG, отдаются как вложения через проверку прав. Встроенного антивируса нет. Публичная форма имеет базовое ограничение повторов по сессии; перед массовой рекламой добавьте ограничение запросов на reverse proxy. События не зависят от cron: открытие работ и решений проверяется сервером при каждом запросе.

Скрипты Docker backup/restore подготовлены, но в текущей среде Docker отсутствует: их полный запуск необходимо проверить после установки Docker. Приложение, миграции и бизнес-сценарии проверены отдельно на установленном PostgreSQL.
